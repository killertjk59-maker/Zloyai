# DuoBozor — Маркетплейси гурӯҳхаридӣ (Pinduoduo барои Тоҷикистон)

**Ҳуҷҷати нақша · Версия 1.0 · 23.10.2026**
Навъи маҳсулот: мобилии iOS/Android (React Native + Expo), панели админӣ дар веб.
Забон: тоҷикӣ / русӣ (i18n, ICU). Асъор: TJS (сомонӣ), нигоҳдории маблағ дар тийин.

---

## 0. Хулосаи иҷроия (Executive summary)

DuoBozor як маркетплейси **гурӯҳхаридӣ (social group-buying)** аст: харидор танҳо
намехарад — ӯ **гурӯҳ месозад** (одатан 2–5 нафар) ва ҳар як иштирокчӣ нархи
пасттар мегирад. Ин ҳастаи стратегияи Pinduoduo аст ва мо онро ба бозори
Тоҷикистон мутобиқ мекунем: WhatsApp/Telegram ба ҷои WeChat, дистрибютори маҳаллӣ
ба ҷои заводи чинӣ, ва **escrow-пардохт** ба ҷои эътимоди бевосита.

Ҷараёни пул, тавре ки шумо талаб кардед:

```
Харидор ──пул──▶ ESCROW (ҳисоби платформа)  ← маблағ «мемонад», на ба фурӯшанда
                        │
                        │  товар расонида шуд + харидор тасдиқ кард
                        ▼
        ┌───────────────┴────────────────┐
        │                                │
  Комиссияи платформа (5–12%)      Бақияи фурӯшанда
        │                                │
   ┌────┴─────┐                          ▼
   │          │                    Payout ба корт/касса
  Админ    Менеджер (бонус)
```

Ягон сомонӣ ба фурӯшанда **пеш аз тасдиқи қабули товар** намеравад. Ин ҳам
ҳимояи харидор аст, ҳам воситаи асосии назорати админ.

## 2. Нақшҳо ва ҳуқуқҳо (RBAC)

Системаи нақшҳо **роль + scope** мебошад (на танҳо enum), то ки оянда
«менеджери категория» ё «менеджери минтақа» илова карда шавад.

| Нақш | Код | Чӣ мекунад | Маҳдудият |
|---|---|---|---|
| Соҳиб/Супер-админ | `super_admin` | Ҳама чиз: танзимот, нақшҳо, комиссия, тасдиқи payout, аудит | 2FA ҳатмӣ, ҳар амал дар `audit_log` |
| Админ | `admin` | Идораи фурӯшандагон, маҳсулот, фармоишҳо, payout, ҳисоботҳо | Наметавонад нақши худро тағйир диҳад, наметавонад `super_admin` созад |
| Менеджер | `manager` | Категория/минтақаи худ: тасдиқи фурӯшанда, ҳалли баҳс, назорати фармоиш, бонуси фоизӣ | Танҳо доираи худ (`manager_scopes`) |
| Дастгирӣ | `support` | Чат, шикоятҳо, баргардонии ≤200 сомонӣ | Бе дастрасӣ ба маълумоти корт |
| Фурӯшанда | `seller` | Маҳсулот, нарх, захира, фармоишҳои худ, бақия, payout | Танҳо дӯкони худ |
| Харидор | `buyer` | Харид, гурӯҳ, ҳамён, рейтинг, баҳс, баргардонӣ | Танҳо маълумоти худ |
| Курер | `courier` | Гирифтан/расонидан, статус | Танҳо фиристодаҳои таъиншуда |

**Қоидаҳои ғафс:**
1. Ҳеҷ кас наметавонад ба пули escrow **бевосита** дастрасӣ дошта бошад — танҳо
   тавассути амалиёти имзошуда (`escrow_release` / `refund`), ки 2 нафар тасдиқ мекунанд
   (4-eye principle) барои маблағи > 2000 сомонӣ.
2. Фурӯшанда наметавонад баъди фиристодан нархро тағйир диҳад.
3. Менеджер наметавонад фармоиши худро ҳамчун харидор ҳал кунад (танҳо `support`/`admin`).

## 3. Ҷараёни пул — Escrow (муфассал)

### 3.1 Ҳолатҳои фармоиш (order state machine)

```
CREATED ─▶ AWAITING_PAYMENT ─▶ PAID_HELD(escrow) ─▶ CONFIRMED ─▶ PACKED
                                                        │
                                                        ▼
                                                   SHIPPED ─▶ DELIVERED
                                                        │        │
                                                        │        ├─▶ COMPLETED (харидор тасдиқ/7 рӯз auto)
                                                        │        └─▶ DISPUTED
                                                        └─▶ CANCELLED (refund пурра)
```

**Ҳолатҳои пул:** `held` → `released` ё `refunded`. Ҳар як гузариш дар
`escrow_events` бо `actor_id`, `reason`, `ip`, `hash` сабт мешавад.

### 3.2 Ҳисобкунии маблағ ҳангоми релиз

```
gross            = 1000.00 TJS          (маблағи харидор пардохткарда)
net              = gross − refunded     (refunded = 0 дар ҳолати муқаррарӣ)
payment_fee      = gross × 1.5%         (арзиши PSP/инкассатсия)
fee_from_seller  = min(payment_fee, net)      ← ҲЕҶ ГОҲ аз фурӯшанда зиёдтар не
fee_absorbed     = payment_fee − fee_from_seller   (талафи платформа)
commission_rate  = 8%                   (аз рӯи категория; 5–12%)
commission       = (net − fee_from_seller) × commission_rate = 78.80
manager_bonus    = commission × 15%     = 11.82   (танҳо менеджери ин фармоиш)
platform_net     = commission − manager_bonus − fee_absorbed = 66.98
seller_payout    = max(0, net − fee_from_seller − commission) = 906.20
```

> **Қоидаи муҳим (санҷида шуд — `tests/test_ledger.py`):** `seller_payout` ҳеҷ гоҳ
> манфӣ намешавад. Ҳангоми баргардонии пурра, PSP-fee **аз фурӯшанда гирифта
> намешавад** — онро платформа мебардорад (`fee_absorbed`). Дар акси ҳол фурӯшанда
> аз фармоиши баргардонидашуда зарар мебинад ва ин бадномии платформа мешавад.

Ҳама дар `ledger_entries` ҳамчун **double-entry** сабт мешавад (дебет = кредит),
то ки ҷамъи ҳама ҳисобҳо ҳамеша = 0. Ин ягона роҳи дурусти молиявӣ аст.

### 3.3 Релиз кай мешавад?

| Ҳолат | Амал |
|---|---|
| Харидор «Гирифтам»-ро пахш кард | Релиз фавран (T+1 барои payout) |
| Харидор 7 рӯз чизе нагуфт | Auto-release (cron) |
| Харидор баҳс кушод | Маблағ мунҷамид мемонад, менеджер ҳал мекунад (SLA 24с) |
| Фурӯшанда 3 рӯз нафиристод | Автоматикан бекор → refund пурра |
| Товар вайрон/нодуруст | Refund пурра ё қисмӣ; арзиши баргардонидан аз фурӯшанда |

### 3.4 Payout ба фурӯшанда

- Бақия = `pending` (escrow-и ҳалнашуда) + `available` (релизшуда − дархостҳо)
- Дархости payout: ≥ 100 сомонӣ, 1 маротиба дар 24 соат
- Админ тасдиқ мекунад → `payout.status = SENT` бо `bank_ref`
- Фурӯшанда метавонад payout-ро ба **ҳамёни дохилӣ** гирад (барои хариди нав)

## 4. Экранҳои асосии мобилӣ

### 4.1 Харидор (Buyer)
1. **Онбординг** — забон, шаҳр, рақами телефон → OTP
2. **Home feed** — баннерҳои акция, «Оҳанрабоҳои рӯз», feed-и тавсиядиҳӣ, карточкаҳо
   бо нишони `🔥 3 нафар аллакай хариданд`
3. **Категорияҳо + Ҷустуҷӯ** (бо филтр: нарх, рейтинг, минтақа, гурӯҳӣ)
4. **Маҳсулот** — галерея, нархи гурӯҳӣ vs нархи оддӣ, таймер, «Гурӯҳ соз» / «Ҳамроҳ шав»
5. **Гурӯҳи ман** — кӣ ҳамроҳ шуд, чанд нафар монд, даъватнома (WhatsApp/Telegram)
6. **Сабад → Checkout** — суроға, интихоби нуқтаи гирифтан, промокод, кэшбэк
7. **Пардохт** — Alipay/Корт/Ҳамёни дохилӣ/Нақдӣ ҳангоми гирифтан; экрани «Маблағ дар
   escrow ҳифз шуд» (ин боварӣ медиҳад)
8. **Пайгирии фармоиш** — timeline, курер, тугмаи «Гирифтам» (бо SMS/OTP тасдиқ)
9. **Ҳамён** — бақия, кэшбэк, ҳамёни escrow («мунҷамид»)
10. **Боғи ман / Referral / Купонҳо / Профил**
11. **Баҳс (Dispute)** — суратҳо, тавсиф, чат бо менеджер

### 4.2 Фурӯшанда (Seller)
1. **Дашборд** — фурӯш, фармоишҳои нав, бақия (pending/available), рейтинг, ҳушдорҳо
2. **Маҳсулот** — CRUD, вариатҳо, захира, нарх, аксияҳо, гурӯҳӣ
3. **Фармоишҳо** — бастабандӣ, чопи этикетка, супоридан ба курер
4. **Payout** — дархост, таърих, ҳисобот
5. **Омор** — фурӯш, конверсия, товарҳои баргардонидашуда
6. **KYC** — ҳуҷҷатҳо, реквизитҳо, шартнома

### 4.3 Менеджер / Админ (веб-панел, mobile-friendly)
Дашборд · Фармоишҳо · Баҳсҳо · Фурӯшандагон (KYC) · Маҳсулот (модератсия) ·
Payout-ҳо · Комиссияҳо · Промокодҳо · Корбарон ва нақшҳо · Аудит-лог · Ҳисоботҳо ·
Танзимот (PSP, SMS, забон, минтақа)

## 5. Архитектураи техникӣ

```
┌──────────────────────────────────────────────────────────────┐
│  МОБИЛӢ (Expo / React Native, TypeScript)                    │
│  expo-router · React Query · Zustand · i18next (tj/ru)        │
│  expo-secure-store (token) · expo-notifications · MMKV cache  │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS + JWT (access 15m / refresh 30d)
┌───────────────────────────▼──────────────────────────────────┐
│  API — NestJS (Node 22, TypeScript) + Prisma                   │
│  REST /api/v1 · OpenAPI · Zod/DTO validation · RBAC guards     │
│  ┌────────────┬────────────┬────────────┬────────────────┐    │
│  │ auth       │ catalog    │ orders     │ payments       │    │
│  │ users      │ groupbuys  │ escrow     │ payouts        │    │
│  │ admin      │ promo      │ disputes   │ reports        │    │
│  └────────────┴────────────┴────────────┴────────────────┘    │
└──────┬───────────────┬────────────────┬────────────────┬──────┘
       │               │                │                │
  PostgreSQL 16    Redis 7          S3/MinIO         BullMQ workers
  (RLS, аудит)   (кэш, rate-limit)  (суратҳо)        (auto-release,
                                                      reminder, ledger)
       │
  PSP: Alipay / Dushanbe City / Кортҳои маҳаллӣ · SMS gateway
```

**Принсипҳо:** idempotency-key барои ҳар пардохт; outbox pattern барои events;
ledger = манбаи ягонаи ҳақиқат; ҳамаи амалҳои молиявӣ immutable (танҳо reversal).

**Панели админ:** Next.js 15 (App Router) + shadcn/ui + TanStack Table, ҳамон API.

**Стек чаро инҳо:** Expo — як код барои iOS+Android, OTA-update; NestJS — модулҳои
пок, DI, тестҳо; PostgreSQL RLS — ҷудокунии доду маълумоти фурӯшанда дар сатҳи база.

## 6. Амният (талаботи пурқувват)

| Соҳа | Чора |
|---|---|
| Аутентификатсия | OTP (SMS) барои харидор; парол + 2FA (TOTP) барои админ/менеджер/фурӯшанда; JWT access 15м + refresh rotation |
| Сессия | Device binding, revocation list дар Redis, logout аз ҳама дастгоҳҳо |
| RBAC | Guard дар ҳар endpoint + RLS дар PostgreSQL; тести автоматии матритсаи ҳуқуқ |
| Молиявӣ | Double-entry ledger; idempotency; 4-eye барои >2000 TJS; ҳамарӯза `ledger_balance == 0` alert |
| Пардохт | Ҳеҷ гоҳ PAN-и корт дар сервер; PSP токенизатсия; webhook-и имзошуда (HMAC + replay guard) |
| Доду маълумот | TLS 1.3, шифр дар ҳолати оромӣ (AES-256), PII-и ҳассос (рақами корт, паспорт) — шифр дар сатҳи сутун |
| Осебпазирӣ | OWASP ASVS L2; rate-limit (Redis); санитайзинг; CSP; нематни HTML аз корбар |
| Фиреб | Velocity check (ҳисоби нав + маблағи калон), device fingerprint, blocklist, KYC-и фурӯшанда, детектори «худхаридӣ» |
| Аудит | `audit_log`-и immutable (append-only), hash-chain, экспорт ба S3, нигоҳдорӣ 3 сол |
| Backup | PITR (WAL), нусхаи ҳар 6 соат, санҷиши барқарорсозӣ ҳар моҳ |
| Мутобиқат | Сиёсати махфият, розигии корбар, ҳуқуқи нест кардани ҳисоб |

**Қоидаи тиллоӣ:** админ **наметавонад** маблағи escrow-ро бе сабаби сабтшуда
(фармоиш + reason code) ҳаракат диҳад; ҳар амали молиявӣ дар `audit_log` бо
`before/after` сабт мешавад.

## 7. Схемаи база

Дар файли `database.sql` — DDL-и пурраи PostgreSQL (40+ ҷадвал, индексҳо, RLS,
триггерҳо, view-ҳои ҳисоботӣ). Хулосаи доменҳо:

```
identity   : users, user_roles, role_scopes, sessions, refresh_tokens, kyc_documents
seller     : sellers, shops, shop_members, seller_payout_accounts
catalog    : categories, products, product_variants, product_media, inventory,
             price_rules, moderation_queue
commerce   : carts, cart_items, orders, order_items, order_status_history,
             shipments, addresses, pickup_points, return_requests
groupbuy   : group_buys, group_members, group_invites
money      : wallets, ledger_accounts, ledger_entries, payments, escrow_holds,
             escrow_events, refunds, payouts, commission_rules, manager_bonuses
growth     : coupons, promotions, flash_deals, referrals, points, gamification
trust      : reviews, disputes, dispute_messages, messages
ops        : notifications, audit_log, settings, feature_flags, jobs
```
