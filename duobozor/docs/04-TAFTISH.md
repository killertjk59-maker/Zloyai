## 2. Хатоҳои ёфтшуда ва ислоҳшуда

### 🔴 2.1 Фурӯшанда ҳангоми баргардонии пурра **−15 TJS** мешуд
**Кӣ ёфт:** `test_ledger.py`, сенарияи 4.
**Мушкил:** формулаи аввал `seller_payout = net − fee − commission` буд. Ҳангоми
`refund = gross` (net = 0) натиҷа `−15.00` мешуд — яъне фурӯшанда барои он ки
мол баргардонида шуд, аз ҷайби худ 15 сомонӣ медод.
**Ҳал:** `fee_from_seller = min(payment_fee, net)`, `seller_payout = max(0, …)`.
Қисми боқимондаи fee — `fee_absorbed` — талафи платформа мешавад.
**Ҳуҷҷат:** `01-NAQSH.md §3.2` навсозӣ шуд.

```diff
- seller_payout = net − payment_fee − commission          // метавонад манфӣ шавад
+ fee_from_seller = min(payment_fee, net)
+ seller_payout   = max(0, net − fee_from_seller − commission)
```

### 🔴 2.2 Ҷадвалҳои `money` ва `ops` ба схемаи `app` мерафтанд
**Кӣ ёфт:** санҷиши ҷойгиршавии ҷадвалҳо (`information_schema`).
**Мушкил:** `search_path = app, money, ops, public` дар болои файл гузошта шуда
буд, вале DDL номҳои ҷадвалҳоро бе схема навишта буд → ҳама 58 ҷадвал ба `app`
мерафт. Ин маънои онро дошт, ки **GRANT/REVOKE барои ҷудокунии дастрасӣ ба
маълумоти молиявӣ имконнопазир** мешуд — яъне тамоми идеяи «money = минтақаи
махдуд» вайрон буд.
**Ҳал:** `SET search_path = money, app` / `ops, app` дар аввали бахшҳо ва
баргардонидан баъд аз онҳо. Ҳоло: **app 44 · money 10 · ops 4**.

### 🟠 2.3 `find_user_by_phone()` пеш аз ҷадвали `orders` сохта мешуд
**Кӣ ёфт:** иҷрои воқеии SQL (`relation "orders" does not exist`).
**Мушкил:** функсия дар бахши 1b буд, ҷадвали `orders` дар бахши 4. `pglast`
инро намебинад — вале Postgres ҳангоми `CREATE FUNCTION` бо `LANGUAGE sql` баданро
месанҷад ва хато медод. Дар истеҳсолот ин маънои **схема тамоман бор намешавад**.
**Ҳал:** функсия ба бахши 14 (охири файл, баъд аз ҳамаи ҷадвалҳо) кӯчонида шуд.

### 🟠 2.4 `normalize_phone('123')` → `'+123'`
**Кӣ ёфт:** санҷиши рақамҳои нодуруст.
**Мушкил:** функсия ҳама чиро қабул мекард, ҳатто 3-рақама. Ин маънои онро дошт,
ки ҳисобҳои «забт» метавонистанд бо калидҳои беэътибор сохта шаванд.
**Ҳал:** санҷиши дарозӣ — E.164 бояд 11..15 рақам бошад, вагарна `NULL`.

```diff
+ IF length(d) < 11 OR length(d) > 15 THEN RETURN NULL; END IF;
```

### 🟡 2.5 Ҳангоми сабти аввалин рақам `phone_history` холӣ мемонд
**Кӣ ёфт:** санҷиши триггер.
**Мушкил:** триггер танҳо `AFTER UPDATE OF phone` буд → рақами ибтидоӣ ҳеҷ гоҳ
ба таърих наменавишт. Баъд аз иваз кардан танҳо як сатр мешуд ва **рақами
кӯҳна гум мешуд**, яъне `find_user_by_phone()` баъд аз 2 иваз метавонист
аккаунтро пайдо накунад.
**Ҳал:** триггер `AFTER INSERT OR UPDATE OF phone`.

### 🟡 2.6 Ду тарҷумаи гумшуда дар `mockup.html`
`«2 нафар монд»` ва `«3 нафар монд»` — `data-ru` надоштанд. Ҳангоми иваз ба русӣ
матн тоҷикӣ мемонд. Ислоҳ: `«Нужно ещё 2»`, `«Нужно ещё 3»`.

## 3. Он чӣ ки **тасдиқ** шуд (на танҳо навишта шуд)

### 3.1 Рақами телефон — 8 формат, 1 аккаунт ✅
```
992921234567 · +992 92 123-45-67 · 0921234567 · 8 (92) 123 45 67
921234567    · 00992 92 123 45 67 · 8 921 234 567 · +992 (92) 123 45 67
                          ↓  app.normalize_phone()
                    +992921234567   →  1 user_id
```
Дар Postgres-и воқеӣ, на дар назария.

### 3.2 Identity: як аккаунт, якчанд калид ✅
- Телефон + Telegram → ду сатри `auth_identities`, **як `user_id`**
- Калиди такрорӣ (`UNIQUE(provider, provider_uid)`) — рад мешавад
- Ивази рақам → кӯҳна ба `phone_history` баста мешавад, нав кушода
- `find_user_by_phone('+992 92 123 45 67')` → «Фарзона Раҳимова» ✓

### 3.3 Ledger: ҷамъи ҳисобҳо ҳамеша 0 ✅
| Сенария | gross | fee | commission | bonus | seller |
|---|---|---|---|---|---|
| Муқаррарӣ 8% | 1000.00 | 15.00 | 78.80 | 11.82 | **906.20** |
| Косметика 12% | 500.00 | 7.50 | 59.10 | 8.87 | **433.40** |
| Refund қисмӣ 300 | 700.00 | 15.00 | 54.80 | 8.22 | **630.20** |

\* `fee_absorbed` — платформа мебардорад, фурӯшанда не.

**10 000 фармоиш** бо 33.33 TJS: escrow = 0.00, кредитҳо = 333 300.00, drift = 0.

### 3.4 Telegram: nonce якдафъаин аст ✅
- 1000 nonce → 1000 гуногун (2^128 вариан)
- nonce-и дуюм → рад
- `auth_date` 299с → қабул, 600с → рад
- Имзои Widget бо формулаи WebApp **тасдиқ намешавад** (фарқи SHA256 vs HMAC)
- `hmac.compare_digest` воқеан вақти доимӣ: 0.196µs vs `==` 0.037µs

### 3.5 Маҳдудиятҳо кор мекунанд ✅
`group_price < base_price` · `payout ≥ 100` · `1 ≤ rating ≤ 5` · `stock ≥ 0` ·
`idempotency_key` (пардохти дубора имконнопазир) · escrow overdraft (релизи бе маблағ рад)
